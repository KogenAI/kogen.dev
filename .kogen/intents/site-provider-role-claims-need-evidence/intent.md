# Tie provider role claims to their evidence

Slug: site-provider-role-claims-need-evidence
Model: not applicable — static page copy, a data file and build-time reading of dist; there is no meaningful state or interacting rules.
Acceptance:
- .kogen/intents/site-provider-role-claims-need-evidence/acceptance.feature
- features/steps/site-provider-role-claims-need-evidence__site.js

Get started (`src/pages/get-started.astro`) and the Providers page (`src/pages/providers.astro`, rows from `src/data/providers.json`) must not claim more for a provider and role than the evidence behind it shows. Each of the 18 provider and role pairs (six providers times Shape, Build, Review) carries exactly one state: `configurable`, `connection tested` or `role verified`, plus an evidence link. The change may touch only those three files, the Markdown twin and llms.txt only where they repeat the changed sentences (both are generated by `scripts/build-agent-content.py` from the pages, so normally no edit), and tests under `features/` or `scripts/`. Pages Functions and any docs file of the KogenAI/kogen repository are out of scope. Existing Get started text outside the sentences named below stays, including the login command for each provider; no emoji is added; `npm run build` keeps passing. The old claims on both pages are replaced, not kept beside the new copy.

Fixed states (decided by the owner; nothing is decided from Studio documents):
- chatgpt: Shape, Build and Review are role verified with model gpt-6.1-sol; effort high for Shape, medium for Build, high for Review.
- anthropic: Review is role verified with claude-sonnet-5-5 at medium; Shape and Build are configurable.
- supergrok, opencode-go and claude-code: all nine pairs are configurable.
- QwenCloud: Build is connection tested (Lab run, model qwen4-max, effort medium, date 2026-11-18); Shape and Review are configurable.
So exactly four pairs are role verified, one is connection tested and thirteen are configurable.

Data (`src/data/providers.json`): each role entry carries its state, an evidence link, and for role verified also the model, the effort and the qualification record path `spec/reference/model-family-qualification.md`; for connection tested also the model, effort and date. The evidence link is `https://app.kogen.studio/workspaces/optimum/projects/kogen/documents/` followed by a document id: `qwen-build-vs-sonnet-20261118` for the QwenCloud Build pair and `providers-role-screen-20261120` for every other pair. Field names are the builder's choice; `scripts/check-providers.mjs` must keep passing and may be updated to the new shape.

Providers page: the table keeps its existing layout of one row per provider with one cell holding the three roles, in the order Shape, Build, Review; the tests locate the 18 provider and role cells in that layout without requiring a new column head. The sixth provider is the row named `openai-compatible` whose instructions link is the QwenCloud setup link (`/get-started/#qwencloud`); the CLI name `openai-compatible` stays because `src/data/cli-provider-names.txt` and `scripts/check-providers.mjs` tie the data to the CLI names. Each role entry in the roles cell starts with the role name and the state, then for role verified the model and effort in parentheses, then the evidence link: for example `Shape: role verified (gpt-6.1-sol, high)` or `Shape: configurable`. The word verified appears on Get started and on the Providers page only as part of the phrase role verified, and only for a role verified pair. A bare `not qualified` or a cell with no state does not appear in the roles cells.

Get started: the sentence about SuperGrok and OpenCode Go becomes `Kogen Loop can be configured with SuperGrok subscriptions, OpenCode Go workspace keys and OpenAI-compatible endpoints; none has a qualified role yet, see Providers.` (the "also supports" wording is removed). The QwenCloud label becomes exactly `experimental: Build connection tested in Lab with Claude Review (qwen4-max, medium); Shape and Review not qualified` and links to `/providers/`. The QwenCloud example line is the `build: {provider: openai-compatible, base_url: https://token-plan.maas.qwencloudapi.com/compatible-mode/v1, model: qwen4-max, effort: high}` line in the code block; it becomes effort medium. The Token Plan note keeps `QwenCloud’s Token Plan terms restrict automation and non-interactive batch use` and its last clause (`so pay-as-you-go suits unattended loops`) is replaced by `the pay-as-you-go URL is configurable and has not been tested through Kogen`. Both pages contain the sentence `The QwenCloud Build evidence came through the fleet proxy; the direct public-install Build is still under test.`
