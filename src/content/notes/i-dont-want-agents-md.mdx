Thariq announced that Claude Code 2.1.277 can read `AGENTS.md` if there’s no project `CLAUDE.md`:

<Tweet id="2101009392611278961" />

I understand why people wanted that. They want to use the same project instructions with different coding agents. I don’t want `AGENTS.md` at all, though, because I’m also using different agents for different jobs, even within one repository.

In that Claude Code release, I also had to account for `AGENTS.md` being a fallback for projects without `CLAUDE.md` or `CLAUDE.local.md`, a setting to read both, and sessions that couldn’t load it directly. A directly loaded `AGENTS.md` didn’t show up with memory files in `/context`, and didn’t fire the instruction-loaded hooks. Which files exist above the working directory, which mode I select, the provider, the installed version and whether another file already imported the instructions all affect what the agent gets.

I already have the builder’s answer. For review, I want another agent to investigate the change and find what’s wrong with it, without first being walked through why the builder thinks it’s right. The instructions for implementing the change would give it that framing. Making the shared instructions read-only wouldn’t work either, because then the builder couldn’t change the code.

I can put exceptions in the file, of course. The planner, builder and reviewer would each need to find the parts addressed to them among the other roles’ instructions. I knew which job I was giving the agent when I started it. I could have just given it the instructions for that job.

There’s another issue with sharing this file between harnesses. I asked about references under the announcement:

<Tweet id="2101036988425974195" />

I got no answer there. The Claude Code documentation says `@path` imports are expanded inside `AGENTS.md`, but that doesn’t make them portable. Some harnesses expand them; others document the Markdown file and their own directory precedence. So I need to know whether the thing I wrote is an instruction to import another file or just some text the agent will see.

We’ve agreed on a filename, and I still have to understand each harness’s discovery, combination and interpretation of it. I want agents to understand the project they’re working on. I also want to choose the context for the work I’m asking them to do, instead of loading instructions for every job into every agent.

In Kogen, I give the planner the job of questioning the request, investigating the software and finding the decisions we still need to make. After we agree on the requirements, the builder can change the code, then another agent reviews it independently. Each gets the instructions, inputs and authority for its job; Kogen doesn’t create project `AGENTS.md` files. If a rule has to hold for all of them, I want the system to enforce it. It shouldn’t depend on whether each model understood my paragraph the same way.
